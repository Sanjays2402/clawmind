## Design notes

### ask --out
Captures answer in memory, writes once at the end. In text mode the
saved file is ANSI-clean and self-contained (sources header + body +
latency footer + optional citations). In --json mode the JSON
payload lands in the file. **Critical**: token-by-token stdout
dribble is suppressed when --out is set so the answer is NOT
rendered twice (terminal + file). Stderr carries the green
"wrote answer (<n> chars) -> <file>" confirmation so a watching
shell still sees the command finished.

### status --check
Body of the response (json or text) is unchanged so a single command
can both report status AND drive the exit code. Non-OK → exit code 2
(NOT 1 — reserved for command crashes so wrappers can distinguish
"ran fine, probe down" from "command crashed"). In text mode also
drops a red "status --check: <down probes> down" line to stderr so
scripts that redirected stdout to /dev/null still get a useful log
line. JSON mode skips the stderr hint to keep parseability.

### forget --confirm <n>
With --apply, does a dry-run pre-flight FIRST to learn the real
count, then proceeds to destruction only when count === N exactly.
The "-1" sentinel is the explicit opt-out for unknown-size scripts
(matches the "no limit" convention elsewhere in the cli). Without
--apply, --confirm is silently ignored (dry-run is already safe).
Error spells out BOTH numbers AND the correct re-run command so the
operator can copy-paste a fix without re-running the dry-run by hand.

### doctor --severity
Display-only filter — exit code is STILL driven by the FULL report's
`ok` flag so hiding warnings can NEVER accidentally hide an error
from CI. Adds two text-mode hints to avoid the "report looks empty
by accident" failure mode: "<n> below --severity X; nothing to
show" when the filter empties the table entirely, and "... <n>
more" at the tail when some rows are hidden. --json mode adds a
new `findingsTotal` field alongside the filtered `findings` array
so a dashboard can show "1 of 3" without re-running the command.

### search --paths-only
Completes the pipeline contract. Deduplicates by path in rank order
(search returns chunk-granular hits so the same file can appear
multiple times under different chunks). Short-circuits before
--json / --out / --highlight / --snippet — the contract is "just
paths, nothing else". Critically does NOT leak the stderr "no
results for foo" hint that would poison `xargs ls`. Threshold +
tag filters still compose naturally (they shape `hits` upstream
of the dedup short-circuit).
