## Theme

Round out the cron pipeline contract:

- **Incremental refresh**: `ingest --since` is the first-class flag a
  cron job needs to do less work. With a 1-hour tick on a workspace
  of tens of thousands of files, the filtered list is tiny —
  near-zero stat() cost vs near-everything hash+manifest cost.
- **Preview before mutation**: `reindex --dry-run` is the safety
  gate for the only other destructive command besides `forget`.
  Same UX pattern (yellow count header, rerun nudge, --paths-only,
  --json).
- **Slim cron snapshots**: `stats --slim` is the JSON shape a cron
  pipeline actually wants — just namespace names plus a total,
  single-line for clean diffing across snapshots.
- **Unified naming**: `stale --paths-only` brings the last list-style
  command in line with the family. Every list command now exposes
  the same --paths-only flag.
- **Quiet operation**: `watch --quiet` is the cron-restarted watcher's
  perfect dance partner — restart marker stays, chatter goes.

## Notable design moments

1. **--quiet test pattern**: the watch action ends with a deadlocking
   `await new Promise(() => undefined)`, so I reused the existing
   sentinel-throw mock for startWatcher and asserted the `onEvent`
   callback the mock captured — then invoked it directly to test
   the suppression. Cleaner than trying to test the production
   chokidar event flow.

2. **--paths/--paths-only OR-merge**: chose to OR the two flags rather
   than pick one. The byte stream is identical so a "both set"
   invocation has zero surprise; the action body short-circuits on
   the single OR, so there's no risk of double-emission.

3. **--slim wins over --compact**: when both reshape JSON output, the
   stricter shape wins. Test pins this precedence so a future
   refactor can't accidentally fall through to the compact-full
   shape after the slim branch handles the request.

4. **ingest --since INCLUSIVE boundary**: the natural cron use is
   "since the previous tick's wall-clock". If --since were
   exclusive, a file modified in the same second as the previous
   tick would be silently skipped — the exact anti-goal of the
   flag. Test pins the boundary explicitly.

5. **reindex --dry-run does NOT load the runtime's heavy deps**: it
   still calls buildRuntime() (for the workspace fallback) but
   never touches the manifest / BM25 / store. A test confirms that
   the dry-run path never reaches the unlink() / ingestCommand()
   calls — if a future regression slips one of those into the dry
   branch, the test will crash on a missing mock.
