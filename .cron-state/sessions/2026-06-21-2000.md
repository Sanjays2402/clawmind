Five features shipped directly on main:

1. **feat(status): add --watch <ms> + --max-polls <n> for a refreshing dashboard** (11718bd)
   Turns the one-shot status into a polling loop. Reuses the same runtime across cycles so per-cycle latency is dominated by the two health probes, not the cli warmup. Text mode in-place re-render on TTY (ANSI cursor-up + clear-line), full per-snapshot print on non-TTY (logs benefit from history). --json mode emits one NDJSON document per cycle (single-line, no indent). --max-polls bounds the loop; without it the loop runs until SIGINT (intercepted for clean exit). --check on a watch loop drives the FINAL exit code (monitoring tool semantics, not circuit breaker — operator wants to see recovery cycles). Validation guards: --watch < 100ms rejected (CPU melt protection), --max-polls non-positive rejected (would defeat the purpose). Refactored snapshotStatus()/renderText()/emitCheckStderr() out of the action body so one-shot and watch cycles produce identical output shapes. +7 tests in status.test.ts (14 total, up from 7).

2. **feat(related): add --above/--below filter pair mirroring feedback list** (a7e8e96)
   Symmetric sibling of --threshold. Strict comparisons (> and <), non-numeric silently ignored (matches --threshold), both flags compose as intersection with each other AND with --threshold. The classic cron use family: `--above 0.9` for the strongest signal neighbours (isolation diagnostic), `--below 0.4` for the weakest survivors (about-to-drop-out diagnostic), `--above 0.5 --below 0.8` for the marginal band, `--threshold 0.5 --above 0.7` for a half-open [0.5,...] hardened by a strict tighter floor. Mirrors `feedback list --above/--below` byte-for-byte for shell muscle-memory. Filter applies BEFORE --paths-only / --json / text rendering and the `count` in --json reflects the filtered length. Client-side filter (API has no minScore/maxScore params today — same precedent as --threshold). +7 tests in related.test.ts (24 total, up from 17).

3. **feat(ask): add --stream-json for live NDJSON event streaming** (75c5e05)
   Bridges the gap between text mode (token-by-token to stdout with ANSI a JSON consumer cannot parse) and --json (assembled payload AFTER LLM completes, forcing UI to wait full latencyMs). Emits one NDJSON document per event as askStream produces them: `{kind:"sources"}` first, then `{kind:"token"}` per token, then `{kind:"done"}` at the end. A live UI sees the citation set up front (sidebar) AND paints the answer letter-by-letter (main panel). Single-line JSON per event so `jq -c .` round-trips cleanly. Pairs with --threshold (skip emits `{kind:"sources"}` + `{kind:"skipped"}`, no tokens, exit 1), --no-citations (drops items[] from sources doc but keeps count marker), and --json (--stream-json wins — streaming contract is stricter). Ignored with --out (live emit vs file capture are incompatible; operator should shell-redirect). Errors emit `{kind:"error"}` as final NDJSON event. +5 tests in ask.test.ts (21 total, up from 16).

4. **test(stale): pin --tsv --since composition byte layout** (4d45a42)
   The --tsv and --since flags landed on stale at different times and were each pinned independently. The combined byte layout — the tab-separated rows that survive the absolute-date filter — was never anchored. Pure regression-guard commit; no source change. Three new tests pin: the base composition (only surviving row in canonical path\\tageDays\\tchunkCount\\tsize\\n shape), the order preservation (no re-sort introduced by --since), and the empty-composition (cutoff dropping every row yields a clean empty stream, wc -l sees 0). +3 tests in stale.test.ts (18 total, up from 15).

5. **feat(watch): add --once --since for one-shot incremental refresh** (8496320)
   Pairs the previous tick's --once mode with `ingest --since` mtime filter so a cron tick can ride out a quiet workspace without re-walking every file. Implementation mirrors `ingest --since` byte-for-byte: cutoff inclusive (>=), parse failures abort up front BEFORE buildRuntime, stat() failures on individual files are non-fatal (silent drop, cron log stays clean). --since is IGNORED without --once (live watcher relies on chokidar to fire on actual file events, so an mtime cutoff would be a confusing no-op). Test approach: added a node:fs/promises mock returning configured mtimes per path, throwing ENOENT for unconfigured paths. +7 tests in watch.test.ts (38 total, up from 31).
