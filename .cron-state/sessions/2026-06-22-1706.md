## What shipped (in commit order)

1. `cec9160` feat(stale): --reverse modifier flips --sort direction
   (establishes family-wide reverse contract). The first --sort-
   bearing command in the cli's family to expose --reverse.
   Implementation: a single sign-flipping multiplier (dir = -1 under
   --reverse, else 1) applied to BOTH the primary comparator AND the
   secondary tie-break by original index. Pinned by a "two consecutive
   runs over identical-ties input produce byte-identical output"
   determinism property test. Cross-mode consistency property (--tsv
   body == --json body) held under --reverse.

2. `c3ab531` feat(search): --reverse modifier flips --sort direction
   (mirrors stale --reverse byte-for-byte). Closes the queued
   "feat(search): add --sort path --reverse" item. Three direction-
   flip cases: --sort score --reverse (weakest-first), --sort path
   --reverse (desc alphabetical), --sort namespace --reverse (desc
   grouping). Composes with --paths-only (dedupe walks post-reverse).

3. `d600337` feat(related): --reverse modifier flips --sort direction
   (completes the queued reverse-modifier family-sweep). The third
   --sort-bearing command. After this commit the family-wide
   reverse-modifier contract is complete across all THREE commands
   the queued list called out. Composes with --above (band-filter
   narrows, sort orders the survivors desc).

4. `4b76cb1` feat(digest): show --paths-only --diff splits emit into
   +/- direction streams. The flat --paths-only walks newSources then
   removedSources for each row, deduped against a SINGLE Set — the
   right shape for "feed xargs ingest with every path the digest
   touched" but NOT for the symmetric "only the NEW paths" use.
   --diff closes the symmetric gap with `git diff`-style prefixes
   (`+ ` for new, `- ` for removed). Critical: TWO SEPARATE dedupe
   sets so a path that appears in both directions across rows
   surfaces TWICE (once per prefix) — the "two different events"
   property pinned by an explicit /shared.md fixture.

5. `b524cb3` feat(feedback): prune --json --slim drops paths array
   for cron-dashboard counts. Mirrors `doctor --json --quiet` and
   `digest run --json --slim`. The full --json shape carries an array
   of every matched path (megabytes on a large workspace); --slim
   drops it for one-line-per-snapshot health checks. Critical:
   errors[] is PRESERVED because per-path failures are exactly what
   a cron dashboard needs to surface. Also pinned: both `threshold`
   and `thresholdAbove` survive under --slim (would-be-regression
   that collapsed them would lie about which predicate ran).
