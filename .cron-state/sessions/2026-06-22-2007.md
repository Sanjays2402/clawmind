## Theme

The family-wide --sort-bearing contract is now uniform across all 8
commands that carry the primitive (stale, search, related, feedback
list, digest list, aliases list, stats, tags list). Every one of them
honours:

1. Primary key per the --sort value.
2. Secondary tie-break by original-input index for cross-snapshot
   determinism.
3. Single dir multiplier under --reverse that flips BOTH (primary and
   secondary).
4. Unknown-key abort with exit 1 enumerating the valid set.
5. Byte-stable output across consecutive runs over identical input.

## Family-contract deviations

Stats and tags are the two family-contract deviations: both have
`--sort` with a commander default value ("namespace" / "count"), so
opts.sort is never undefined and `--reverse` is ALWAYS active. The
rest of the family treats `--reverse` without `--sort` as a no-op
because opts.sort IS undefined. Both deviations are documented
explicitly in the corresponding --reverse help text AND in the test
comments — a future reader sees the precedent rather than guessing.

## Per-feature design notes

### feedback list --reverse (32580ff)

Three interesting choices pinned:
- `--sort boost --reverse` asc surfaces the "which paths are getting
  penalised hardest by feedback" question.
- `--reverse` without `--sort` silently ignored (matches family contract).
- `--sort downs --reverse --top 5` is "the 5 entries with the FEWEST
  downvotes" — composition pin that --top applies to the head of the
  post-reverse ordering.

### digest list --reverse (6777c44)

The subtle pin: under `--sort lastRunTs` the default treats null as
-Infinity (sorts to top under asc = "most overdue"). Under `--reverse`
the dir multiplier flips that to sort-to-bottom, which is the
colloquially correct reading — a never-run digest cannot be "most
recently run". A dedicated test pins this so a naive refactor that
special-cased null OUTSIDE the multiplier would surface immediately.

### aliases list --reverse (4bfe9b3)

The natural use is `--sort createdAt --reverse` for the "alias added
at-or-after this cutoff with the LONGEST track record" question,
complementary to the "freshest first" default that --since alone
surfaces.

### stats --reverse (4e73f71) — FAMILY-DEVIATION #1

Numeric keys (files/chunks/bytes) use the dual-flip multiplier as the
other ports; namespace/name (which has no ties — each namespace name
is unique server-side) uses a plain Array#reverse() since reversing
asc-alphabetical is observationally indistinguishable from a
localeCompare * dir sort.

### tags list --reverse + secondary-index sort (ba77780) — FAMILY-DEVIATION #2

TWO ENTANGLED SLICES IN ONE COMMIT. The --reverse dual-flip multiplier
needs a real local sort with a secondary index key to flip, and the
queued list explicitly called out the tags secondary-index sort as
missing under "verify the secondary-by-original-index sort is in
place; if not, add it". Both shipped together.

The previous code path was:
- `--sort count`: pass-through (API order, ties broken alphabetically
  by the API but unenforced cli-side).
- `--sort tag`: localeCompare, no secondary key.

Both paths are now unified through a single map-sort-map pipeline with
the dir multiplier and the secondary-index key, mirroring the shape of
every other family member. The `--sort count` output is observationally
identical on the existing FIXTURE_ITEMS (no ties) but the contract is
now enforced rather than incidental — a future API-side change that
returned items in a different order would NOT silently change the cli
output.
