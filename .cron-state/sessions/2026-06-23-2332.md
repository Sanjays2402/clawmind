## Critical design notes

- **Toast tone -> duration map** (success 3.2s, info 4.2s, error 6.5s)
  so failures stick long enough to actually read. Hard-cap of 6 toasts
  in the viewport stack so a runaway loop cannot push the UI off-screen.
- **'?' shortcut input-guard**: the binding is suppressed when the
  keystroke originates from INPUT/TEXTAREA/contentEditable. Without
  this, typing '?' into the composer would clobber the keystroke and
  pop the help sheet — a regression worse than not having the shortcut.
- **Skeleton bar widths**: stepped widths in each paragraph block
  (94/98/72, 96/89/92/58, 83/44) so the silhouette reads as prose,
  not as a rectangle. The eye latches onto the long-short-long visual
  rhythm of real text.
- **SourcesPane citation-number stability** (the SUBTLE bug I caught
  in design): the numbered pill on each card must use the source's
  ORIGINAL index in the unfiltered list, NOT its index in the filtered
  subset. If filtering renumbered the pills, citation [3] in the answer
  text would silently point at the wrong source. Pinned by computing
  `sources.indexOf(s)` for the pill rather than the map index. Took
  30 seconds of thought to anticipate; would have been a nasty bug to
  find post-ship.
