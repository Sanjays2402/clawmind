## Critical design notes / decisions

- **No SSR hydration mismatch (slice 1):** the old useTheme used
  `useState(read())` which read localStorage during render — fine on client but
  the new OS-detect could disagree with the server-rendered `data-theme="light"`.
  Fixed by resolving the real theme in a mount EFFECT, not the initialiser, so
  the first paint always matches the light default and the real theme lands one
  paint later. System changes deliberately don't persist to localStorage, so
  OS-follow keeps working until the user makes an explicit toggle (which pins).
- **Skip-link target placement (slice 2):** the landing span is a tabindex=-1
  `<span id="cm-content">` placed AFTER the header (incl. the mobile nav, which
  lives inside the header), so focus lands genuinely past all nav. TopNav had to
  be wrapped in a fragment to host both the skip anchor (before header) and the
  target (after header). Typecheck confirmed the JSX is valid — an LSP partial-
  view diagnostic flagged a false "unexpected token" mid-edit that the real tsc
  run cleared.
- **aria-current reuses `active` (slice 3):** both nav loops already compute
  `active` for the highlight; surfacing it as `aria-current="page" : undefined`
  means the two signals are derived from one source and can't drift.
- **:focus-visible not :focus (slice 4):** pointer clicks must NOT show a ring
  (that's the whole point of focus-visible). The base rule is element-level
  specificity so the four existing bespoke focus treatments (cite pill, skip
  link, open-viewer, share CTA — all class selectors) override it without
  needing !important. Checked there's no `outline:none` reset that would defeat
  it (only the intentional .cm-skip-target one).
- **Server-titled routes left untouched (slice 5):** the resolver returns null
  for trust/incidents/sbom/breach-register/offline (and /settings/incidents,
  /settings/trust) — these own their title via server generateMetadata, and the
  DocumentTitle effect skips null so it never clobbers them. Opaque-id detail
  segments (hashes, numeric, >24 chars) are skipped so /tags/<hash> reads "Tags"
  not "<hash> · Tags", while real labels like /tags/work -> "Work · Tags". Home
  resolves to the bare brand "ClawMind". Validated all of this against 12 sample
  paths with an inline node script before committing.
