## Shipped (5 features, 5 commits, pushed 1bba1b8..f62caa8)

1. **`feat(web/chat): clickable starter prompts`** (4eda6ad)
   - The empty-state "a few things to try" list rendered as plain text — a
     first-run reader had to retype a starter by hand.
   - Hoisted `STARTER_PROMPTS`; `EmptyReading` now takes `onPick` and maps each
     to a `cm-starter-prompt` button (lead arrow slides in on hover/focus,
     accent-soft wash). `pickStarter` sets the question + bumps `composerFocus`
     so the caret lands at the end, ready to tweak or submit.
   - Reduced-motion guard drops the arrow slide.

2. **`feat(web/chat): "/" focuses the composer`** (473d967)
   - No keyboard way back to the composer once focus wandered (pill, rail, click).
   - Global `keydown` on the chat page bumps `composerFocus`; suppressed in
     inputs/textareas + when a modifier is held (cmd+/ stays the saved-prompt
     picker); `preventDefault` stops the slash typing into the field.
   - Registered in ShortcutHelp Chat group + advertised in the breadcrumb hint.

3. **`feat(web/chat): floating "jump to latest"`** (9e48f47)
   - During a long streaming answer, scrolling up to re-read lost the live edge.
   - New `JumpToLatest` watches a sentinel (`id=cm-stream-end`) at the bottom of
     the answer column with an IntersectionObserver (the BackToCited pattern).
     Accent-tinted pill with a breathing `cm-stream-dot` shows only while
     streaming AND the reader is above the edge; smooth scroll back,
     reduced-motion aware. Sentinel is `aria-hidden`.

4. **`feat(web/sources): deep-link rows into the viewer`** (b805f38)
   - `/sources` rows only had a capped 200-line inline preview; the rich
     `/sources/view` (highlighting, line numbers, wrap, cited context, related)
     was unreachable.
   - Hover/focus-reveal `.cm-open-viewer` corner link on every row (reuses the
     chat rail affordance; stops click propagation so it never re-selects the
     row) + a first-class "Open in viewer ->" button in the detail header. Both
     deep-link by real path.

5. **`feat(web/sources/view): per-file-type wrap memory`** (f62caa8)
   - The wrap toggle persisted one global boolean (`cm-code-wrap`) so wrapping a
     `.md` also wrapped every `.ts` — but prose and code want opposite defaults.
   - New `lib/wrapPref.ts` owns an ext->bool JSON map (`cm-code-wrap-by-ext`)
     with a pure core: `extOf` (dotfile/multi-dot/no-ext safe),
     `defaultWrapForExt` (prose wraps, code scrolls), `resolveWrap` (precedence
     explicit per-ext > legacy global > default), immutable `nextWrapMap`,
     defensive parsers. Legacy key honored as a fallback so no setting is lost.
   - `CodeView` seeds the per-ext default on SSR + first render (no hydration
     mismatch) then applies the resolved pref in a path-keyed mount effect.
   - Verified the pure core with a 36-case node harness.
