# Tick 2026-06-26 06:49 PDT — everyday navigation + secondary surfaces, on-brand

**Identity:** Cake (cron). Branch: `main`. Focus: FRONTEND override (apps/web/).

**Theme:** Make everyday navigation and the secondary surfaces feel finished and
ON-BRAND. Two of the app's pages were rendering in the wrong palette entirely;
the command palette (hit every session) couldn't reach a third of the app; the
stats page had no proportion view. Five distinct slices closing those gaps.

## Shipped (5 features, 5 commits, pushed 89292d4..11fa810)

1. **`feat(web/usage): re-theme + request-mix bar`** (c6fd748)
   - /usage used foreign CSS vars absent from the cm-* set (var(--bg),
     var(--border), var(--fg-muted)) + hard-coded bg-violet-500 / bg-red-500 /
     bg-amber-500 — it rendered in the WRONG palette. Swapped everything for
     cm-* (cm-card, text-cm-muted, warm quota tints accent->cite-gold->danger).
   - Added a "Request mix" panel: a two-segment ask-vs-search proportion bar
     (accent + cite gold) with a percent-share legend, from the existing
     usage.byKind payload. The page previously showed the two counts as bare
     numbers; this turns them into a shape.

2. **`feat(web/welcome): re-theme onto the cm palette`** (8bb916a)
   - The onboarding guide's progress bar, next-step ring, step rings and
     completed checks all used var(--accent,#22c55e) — a GREEN fallback
     unrelated to the warm-orange brand — plus var(--bg-elev) and text-red-500.
   - Moved to bg-cm-accent / cm-subtle / cm-border; next-step emphasis is now an
     inset accent-line box-shadow (the calm stats stat-card treatment); the
     all-set check reads in cm-success, the seed error in cm-danger. Pure
     restyle — seed/skip/reset/progress logic untouched.

3. **`feat(web/nav): command palette reaches every nav surface`** (840181f)
   - The palette (mod+K) listed 18 routes while the TopNav exposes ~27, so ~a
     third of the app (Explain, Collections, Feedback, Webhooks, Shares, Inbox,
     Batch, Usage, Admin, Welcome) was unreachable by keyboard jump.
   - Added the 10 missing surfaces (primary-then-secondary order mirroring the
     More menu), fixed two icon mismatches (Settings was IconChartBar, shared
     with Stats/Usage), raised the result cap 24->40 so an empty query reveals
     the whole route list plus recent history.

4. **`feat(web/nav): recent-pages section in the command palette`** (49abbd8)
   - Frequent jumps showed the same static list every open. New
     lib/recentPages.ts owns a localStorage MRU with a pure, tested core:
     parseRecent (defensive JSON), pushRecent (move-to-front / dedupe / cap /
     immutable), bestRouteHref (collapse a visited path onto its owning route —
     /settings/security -> Settings; most-specific wins; query/hash/slash
     tolerant). RecentPagesRecorder (mounted in the layout) records each nav.
   - The palette builds up to 5 recent rows on open (collapsed to known routes,
     current page dropped, deduped, reusing each route's icon+label). On empty
     query they lead under a "Recent" label + "Jump to" divider, with their
     routes removed from the main list so nothing reads twice; they fold away
     once the user types. 27-case tsx harness.

5. **`feat(web/stats): namespace-share donut alongside the bars`** (11fa810)
   - The stats page ranked namespaces by magnitude (bars) but had no view of
     relative weight. New dependency-free lib/donut.ts (polarToXy 0deg-at-12,
     ringArcPath largeArc + full-ring-split, donutSegments drops zero/NaN/neg &
     normalizes, fmtShare <1% floor) — NO Recharts/D3, stays out of the bundle.
   - NamespaceDonut: ring + legend driven by the SAME files/chunks/bytes metric
     toggle as the bars; cm-* derived palette; long tail folds into one "Other"
     slice; SVG aria-hidden with per-slice <title>, legend carries the
     accessible name/value/share table; center shows the dominant share. Only
     renders when >1 namespace. 32-case tsx harness.
