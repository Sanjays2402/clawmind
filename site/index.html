Why did we pick LanceDB over pgvector?

You chose LanceDB because it runs embedded in the API process, so there's no separate database to manage on a laptop 1. The decision note also mentions that its on-disk columnar format made re-indexing a 40k-chunk workspace fast enough to run on every save 2.

pgvector stayed on the list as an optional backend for teams that already run Postgres 3

How it works

From files on disk to a cited answer.

Ingest

Walks the workspace with a gitignore filter, skips unchanged files by hash, and loads markdown, code, JSON, PDF, and HTML.

Embed

Chunks go to a local MLX sidecar running bge-small-en-v1.5, with an OpenAI-compatible fallback.

Store

Vectors go to LanceDB and tokens go to a BM25 index, both on your disk.

Retrieve

Lexical and dense search run in parallel, then are blended, reranked, and diversified to fit a token budget.

Answer

The LLM streams prose over SSE, and each [n] mark resolves to a file and line range.

Get started

Running in about five minutes.

You need Node 20.10+, pnpm 9, Python 3.11+, and an OpenAI-compatible chat endpoint, which can be a local one.

terminal
$ git clone https://github.com/Sanjays2402/clawmind.git && cd clawmind
$ pnpm install && cp .env.example .env
# start the embedding sidecar (port 7411)
$ (cd packages/embed/python && pip install -r requirements.txt && python server.py) &
# API on 7410, web UI on 7412
$ pnpm dev
# in another shell: index the samples and ask
$ pnpm clawmind ingest ./samples
$ pnpm clawmind ask "where did I first sketch the citation rail idea?"
